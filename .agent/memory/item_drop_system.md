# Skill: Map Item & Drop System

## 1. Overview
This system handles items falling on the ground (from mob drops or manual drops) and the logic for players picking them up.

## 2. Item on Map (ItemMap)
Structure located in `src/map/models/item_map.rs`.
- **Identity**: Each ground item has a unique `item_map_id` (short-lived, generated by `ItemMapService`).
- **Ownership**: 
  - `player_id`: The ID of the person who dropped it or killed the mob.
  - `OWNER_RESET_TIME_MS` (45s): After this time, anyone can pick up the item.
  - `ITEM_EXPIRE_TIME_MS` (50s): After this time, the item disappears from the map.
- **Special Items**: Some items (Dragon Balls, DHVT items) have no expiration or specific ownership rules.

## 3. Mob Drop Logic
Logic located in `src/map/services/mob_service.rs`:
- When a mob dies, `drop_item_on_mob_death_actor` is called.
- Rewards are calculated in `get_mob_rewards` based on:
  - Map ID (e.g., beginner maps).
  - Mob Template ID.
  - Player's current Task ID/Index (Quest items drop only if the player is on that quest).
- **Process**:
  1. Calculate rewards -> `Vec<Item>`.
  2. For each item, create an `ItemMap` entity.
  3. Add to `zone.active_items`.
  4. Broadcast `Message(68)` (Item Appear) to all players in the zone.

## 4. Item Pickup Logic
- When a client sends a pickup request, it is routed to `PlayerActor` then `ZoneActor`.
- **Check**: `item.can_pickup(player_id, clan_id)` verifies if:
  - The player is the owner.
  - The ownership timer has expired (`-1`).
  - The player is in the same clan (if `clan_id` is set on the item).
- **Result**: If successful, the item is added to the player's inventory, and `Message(-19)` (Pickup Success) is broadcast.

## 5. Network Messages
- `Message(68)`: Item appears on map.
- `Message(-21)`: Item disappears from map.
- `Message(-19)`: Pickup notification.
- `Message(-20)`: Request to pick up item (Incoming).
